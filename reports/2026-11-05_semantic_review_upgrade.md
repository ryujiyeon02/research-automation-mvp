# 의미 검토 개선 실험: 미완료

2026-11-05에 원인·결과 뒤집기와 잘못된 채택·제외를 줄이는 작업을 실행했습니다.
원본 보존과 검사 장치는 구현했지만 **실제 문서의 정상 주장까지 과하게 제외하는 문제가 남아 있습니다.**
자동 의미 검수가 해결됐거나 운영 정확도가 검증됐다고 설명할 수 없습니다.

## 실제로 바꾼 것

- 여러 주장을 한꺼번에 판단하지 않고 주장별로 원문의 역할·상태·범위·전망 여부를 읽습니다.
- 후보의 방향·modality·전달 경로를 해당 원문 속성 읽기에서 분리하고, 코드가 값들을 비교합니다.
- 일부 명시적 영어·한국어 인과 구문은 규칙으로 확인합니다. 해석할 수 없는 조건은 보류합니다.
- 인용문을 다시 생성하는 대신 원문 문장 번호와 실제 텍스트·위치를 연결합니다.
- 단계별 형식 오류는 한 번만 재시도하며, 원본 응답과 검사 전 후보·판정 이유를 모두 보존합니다.
- Homebrew 실행본의 구조화 출력 실패를 피해 같은 버전의 공식 Ollama 실행 환경에서 JSON Schema 강제를 확인했습니다. 기존 모델을 재사용했으며 추가 모델은 다운로드하지 않았습니다.

공식 실행 환경은 Git에서 제외한 `data/ollama_runtime/v0.40.14/`에 약 609MB를 차지합니다.
설치 도구는 공식 배포본의 SHA-256을 검사합니다. `.env`의 프로젝트 엔드포인트만 11435로 바꾸었으며 다른 키를 변경하지 않았습니다.
검증 후 전용 서버를 종료해 모델 메모리를 반환했습니다. 필요할 때 `scripts/local_ollama.py serve`로 시작할 수 있습니다.

재현 시험은 같은 요청에 저장된 응답을 돌려주는 방식이며 새로운 모델 실행과 구분해야 합니다.

## 남은 문제

실제 AMD 실행에서는 변수 이름에 상태·비교 기준이 빠졌다고 판단하거나 수준과 변화 상태를 혼동해 과도하게 제외했습니다.
원문에 충실한 주장인지와 현재의 문자열 표현 규칙을 만족하는지는 같은 문제가 아닙니다.
인공 사례의 판정 개선을 실제 문서의 유효성으로 확대 해석해서는 안 됩니다.

현재 기본 동작은 후보와 기록 보존입니다. 모델 통과를 인간 검수나 인과 검증으로 승격하지 않으며 DB에 자동 반영하지 않습니다.
다음 검증에는 변수의 이름·변화 상태·비교 기간을 분리한 계약과, 독립적으로 확인한 실제 문서 사례가 필요합니다.
이 작업을 완료했다고 표시하지 않습니다.
