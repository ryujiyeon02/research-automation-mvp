# Ollama 의미 검토 실행 확인: 2026-11-05

원본 응답 보존과 별도 의미 검토를 추가한 뒤 실제 로컬 `qwen3.5:9b`로 실행했습니다.
실행 자체는 확인했지만 최종 판정을 이 모델에 전부 맡길 수준은 확인하지 못했습니다.
이 결과를 보고 CLI와 날짜별 실행기의 기본값을 **후보 파일 보존만 수행**하도록 변경했습니다.

## 7개 주장 검토

`scripts/evaluate_claim_review.py`로 3개 원문 묶음, 7개 주장을 검토했습니다.
과거에 보존된 오해석 3개와 Codex가 만든 정상 대조 주장 3개, 원인·결과를 뒤집은 인공 예시 1개입니다.
기대 판정도 Codex가 작성했습니다. 독립 전문가 정답이나 새로운 문서에 대한 정확도 벤치마크가 아닙니다.

기대 판정과 일치한 결과는 **4/7**입니다. 특히 기존에 보수적으로 제외한 주장 36을 새 검토자가 통과시켰습니다.
이 주장은 전달 경로 필드에는 판매 감소를 담고 있지만 그래프의 원인·결과 필드가 충분히 구체적이지 않아 이전 검토에서 제외한 사례입니다.
원인·결과·조건을 각 필드에 얼마나 엄격하게 명시해야 하는지 판정 기준 자체의 정교화도 필요합니다.

제외된 사례도 올바른 해설을 보장하지 않습니다. 한국은행 주장 33을 제외한 검토 사유에는 금리 서술을 가격으로 오독한 부분이 있었습니다.
BEA 정상 대조 주장에서는 같은 문단 앞부분의 비국방 지출 맥락을 충분히 반영하지 않았습니다.
따라서 단순히 제외 건수만 세어 의미 검증이 성공했다고 설명할 수 없습니다.

BEA 묶음의 첫 검토는 `reason` 길이 제한 위반으로 JSON 스키마 검증에 실패했습니다.
1회 재시도 후 유효한 응답을 얻었으며 실패한 응답도 보존했습니다.
모델 생성 응답은 총 4회, 최초 스키마 미지원 501을 포함한 HTTP 요청은 5회입니다.
서버가 보고한 토큰 합계는 입력 4,978, 출력 3,835입니다. 로컬 모델의 사용량이며 Codex 토큰이나 청구액을 뜻하지 않습니다.

공개 수치·판정은 [JSON 요약](2026-11-05_semantic_review_check.json),
실제 입력과 HTTP 응답은 Git에서 제외한 `data/review_evaluations/20261105T041930593112Z/`에 있습니다.

## 실제 AMD 문서의 전체 경로

기존 DB 문서 12의 실제 원문에서 2,400자까지 입력해 추출과 검토를 이어 실행했습니다.

- 첫 구현 점검: 추출 4개 중 근거 불일치 1개 제외. 나머지 3개를 의미 검토하여 2개 제외, 1개를 `reported_claim`으로 저장했습니다.
- 7개 표본에서 모델의 판정 문제를 확인한 뒤 기본 DB 반영을 해제했습니다.
- 변경 후 같은 명령 재실행: 추출 4개 중 근거 불일치 1개 제외. 검토 응답이 두 번 모두 유효한 JSON이 아니어서 나머지 3개 전체를 보류했습니다. DB 추가는 0개입니다.
- 재실행 기록은 `data/review_evaluations/amd_candidate_only_stdout.json`과 연결된 pipeline·extraction·review 파일에 있습니다.

두 번째 실행에서 JSON 문자열에 작은따옴표를 사용한 모델 응답이 나왔습니다. 파서를 느슨하게 바꾸어 통과시키지 않았습니다.
Ollama 서버의 JSON Schema 강제가 없는 환경에서는 프롬프트에 스키마를 넣어도 유효한 JSON이 보장되지 않습니다.
이 환경은 첫 501 응답 후 스키마를 프롬프트로 전달하고 Pydantic으로 다시 검증하는 방식입니다.

## 이번에 확인한 것과 남은 일

- 원본 응답과 검사 전 주장, 제외·보류 이유가 보존됩니다. 시간 초과에는 수신하지 못한 응답을 만들어 저장하지 않습니다.
- 검사 실패가 조용히 통과로 바뀌지 않고 최대 1회 재시도 후 보류됩니다.
- 기본 경로는 후보 기록만 저장합니다. DB 반영을 선택해도 모델 통과 후보는 미검증 `reported_claim`입니다.
- 자동 테스트 60개와 Ruff가 통과했습니다. 테스트는 저장·검증·분기 동작의 확인이며 모델 정확도 증명이 아닙니다.
- Codex는 구현, 테스트 기대값 작성, 이 실행의 결과 해석을 담당했습니다. 운영 경로의 모델 호출은 Ollama가 담당합니다. 사용자 또는 독립 분석가가 검수했다고 표시하지 않습니다.

다음 단계는 필드별 판정 기준을 명확히 한 뒤 사람이 확인한 정상·오류 사례를 늘리고,
누락·잘못된 채택·과도한 보류를 각각 평가하는 것입니다. 그다음 다른 검토 모델과 비교해야 합니다.
검증 전에는 모델의 통과 판정을 자동 확정하거나, 원문에 근거가 있다는 이유로 경제적 인과가 입증됐다고 표현할 수 없습니다.
