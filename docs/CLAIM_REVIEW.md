# 인과 주장 보존과 의미 검토

2026-11-05에 추가한 자동 검토 단계입니다. 11월 4일 실행에는 적용되지 않았습니다.

기존 코드는 모델 응답을 파싱하고 근거 문구가 실제 입력에 있는 주장만 반환했습니다.
그 전 응답과 제외한 주장을 저장하지 않은 것은 실행 기록 설계의 누락입니다.
토큰 절약을 위해 생략해야 하는 작업이 아니었습니다. 이미 보존하지 않은 과거 응답은 복원할 수 없습니다.

## 현재 실행 순서

```text
원문 DB → 관련 문단 선택 → Ollama 추출 → 원본 HTTP 응답 저장
  → JSON/Pydantic 검사 → 근거 문구 일치 검사
  → 별도 Ollama 의미 검토 → 검토 원본 저장 → 검토 인용문 일치 검사
  → supported / rejected / held 결정 → 후보 파일 보존 (기본 DB 반영 없음)
```

CLI의 `extract-claims`와 `scripts/research_pilot.py --stage extract`가 이 경로를 사용합니다.
저수준 `OllamaClient.extract_claims()`는 근거 일치 검사까지 수행합니다.
새 호출부에서는 `extract_reviewed_claims()`를 사용해야 의미 검토를 거칩니다.

## 어떤 오류를 검사하는가

| 항목 | 질문 |
| --- | --- |
| cause_effect | 원인과 결과가 뒤집혔거나 상관관계를 인과로 바꾸었는가? |
| direction | 결과의 증가·감소 방향을 잘못 읽었는가? |
| scope | 정부 소비를 전체 소비로 바꾸는 등 대상이 달라졌는가? |
| qualifiers | 판매 감소를 단순 판매로 바꾸거나 조건·비교 기준·시차를 빠뜨렸는가? |
| modality | 전망·가능성을 이미 발생한 사실로 바꾸었는가? |
| channel | 원문에 없는 전달 경로를 외부 지식으로 보충했는가? |

각 항목은 supported, contradicted, uncertain 중 하나입니다. confidence 점수만으로 채택하지 않습니다.

- 검토자의 원인/결과 인용문도 원문에 있어야 합니다. 없는 인용문은 `held`입니다.
- 하나라도 contradicted이면 `rejected`, uncertain이면 `held`입니다.
- 모든 항목이 supported이고 인용문이 일치해야 `supported`입니다.
- JSON 오류, 누락·중복·범위 밖 주장 ID, 연결·응답 오류는 한 번만 재시도합니다.
- 두 번 모두 실패하면 해당 검토 묶음 전체를 `held`로 남깁니다. 기각된 주장은 재시도하지 않습니다.
- 검토 입력이 보수적으로 정한 문맥 예산(프롬프트·스키마 포함 UTF-8 12,000바이트)을 넘으면 요청하지 않고 보류합니다. 긴 문서 자동 분할은 아직 없습니다.
- 기본 동작은 후보 파일 보존이며 DB의 `causal_claims`에 추가하지 않습니다. 실제 소규모 실행에서 기존 제외 주장을 통과시킨 결과를 보고 자동 반영을 기본 해제했습니다.
- `--store-model-supported`를 명시한 경우에만 supported 후보를 DB에 넣습니다. 그 경우에도 상태는 미검증 `reported_claim`입니다. 모델 통과를 인간 검수나 인과 검증으로 승격하지 않습니다.

## 보존하는 기록

`data/llm_runs/` 아래에 고유 ID로 생성합니다. `.gitignore`의 `data/` 규칙이 적용됩니다.
원문에 공개되지 않은 정보가 포함될 수 있으므로 기록 전체를 GitHub에 올리지 않습니다.

| 파일 | 내용 |
| --- | --- |
| `extraction-*.json` | 실제 입력·프롬프트·스키마, HTTP 응답 원문, 파싱 전후 상태, 근거 검사 전 주장, 제외 이유 |
| `review-*.json` | 별도 검토 요청과 응답 원문, JSON 검증 성공·오류 |
| `pipeline-*.json` | 후보 전체, 문서 ID·URL·내용 해시, 위 파일 연결, 주장별 채택·제외·보류 이유 |

원본 응답은 파싱보다 먼저 저장합니다. 잘못된 JSON도 보존합니다.
HTTP 응답 자체가 오지 않은 연결 오류·시간 초과에는 요청과 오류 종류만 남습니다.
서버가 JSON Schema를 지원하지 않아 재요청한 경우 첫 501 응답도 저장합니다.
환경변수 전체, 요청 헤더, 증권사 키·계좌는 이 기록에 넣지 않습니다.

## 비용과 한계

정상 입력에는 추출 1회와 검토 1회가 필요합니다. 검토 응답이 깨지면 검토가 최대 2회입니다.
모델 서버의 스키마 미지원 501에 대한 형식 전환 요청은 별도이며 생성 토큰이 없는 실패일 수 있습니다.
응답 저장 자체는 LLM을 다시 호출하지 않습니다. Codex는 이 실행 경로에 없습니다.

현재 추출과 검토는 같은 로컬 `qwen3.5:9b`를 사용합니다. 호출을 분리해도 모델 오류가 독립적이지 않습니다.
검토자가 똑같이 오독하면 잘못된 주장이 통과할 수 있고, 정상 주장도 보류·제외할 수 있습니다.
원문의 주장 자체가 사실인지는 이 단계가 검증하지 않습니다. 원문에 있는 주장과 경제적 인과의 진실은 다릅니다.
검토 사유도 모델 생성물이므로 정확한 해설로 그대로 인용해서는 안 됩니다.

실행 평가에는 기존 오해석과 정상 대조 주장, 원인·결과 뒤집기 예시를 함께 넣었습니다.
기대 판정은 Codex가 작성했으며 독립 전문가의 정답이나 정확도 벤치마크가 아닙니다.
실행 방법:

```bash
PYTHONPATH=. uv run python scripts/evaluate_claim_review.py
```

결과는 고유 실행 폴더 `data/review_evaluations/<run_id>/`에 저장합니다.
개별 실행 결과와 발견한 한계는 공개 실행 보고서에 따로 기록합니다.
